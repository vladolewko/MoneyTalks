## Зміст

| Документ | Зміст |
|----------|--------|
| [README.md](./README.md) | Індекс документації та правила її оновлення |

Ці файли описують поточний стан MVP і цільовий розвиток додатку. Код залишається джерелом правди для схеми БД; **контракт публічного API** дублюється в згенерованих артефактах Scribe у `backend/public/docs/`.

## Швидкий маршрут по документації

- Якщо треба зрозуміти, **що за продукт**: починай з [TZ.md](./TZ.md).
- Якщо треба зрозуміти, **що вже можна показувати в мобільному клієнті**: дивись [MOBILE_MVP.md](./MOBILE_MVP.md).
- Якщо треба зрозуміти, **як це запускати локально**: дивись [TECH_STACK.md](./TECH_STACK.md).
- Якщо треба змінювати або перевіряти **REST API контракт**: дивись [API.md](./API.md).

## Оновлення API-документації (коротко)

Будь-яка зміна маршрутів, параметрів, валідації або формату JSON-відповідей має супроводжуватися:

1. Оновленням атрибутів Scribe / описів на відповідних контролерах у `backend/app/Http/Controllers/Api/`.
2. Запуском `composer run docs` у `backend/` і комітом оновлених файлів у **`backend/public/docs/`**.

Деталі та обґрунтування — у [TZ.md § 4.5](./TZ.md#45-документація-api).

## Оновлення mobile-документації

Якщо змінюється демонстраційний сценарій або UX мобільного клієнта, потрібно:

1. Оновити короткий опис у [MOBILE_MVP.md](./MOBILE_MVP.md).
2. За потреби синхронізувати статуси вимог у [TZ.md](./TZ.md).
